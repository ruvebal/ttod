# FE II teaching-skeleton rationale and calendar

**Status:** PROPOSED research-side planning amendment

**Engineering plan:** [`PHASE-U-FEII-TEACHING-SKELETON-CASCADE.md`](../DEV_PLAN/PHASE-U-FEII-TEACHING-SKELETON-CASCADE.md)

## Rationale

The proposed teaching artifact is neither the rich instructor reference nor an empty starter. It is
a complete, locally runnable vertical slice in which R3b–R7 are present at hello-world depth. The
instructor uses the connected system to explain front-end foundations before students collaborate;
students then expand those same seams as assessed work.

The research proposition is deliberately modest: a minimal complete system may make architectural
boundaries more observable while preserving authentic design work. This is a design rationale, not
evidence that learning improves. Any later educational claim must be grounded, approved, and based
only on consented evidence collected without affecting course access or grades.

The design distinguishes:

- **feasibility evidence:** the richer instructor reference proves the architecture can be built;
- **teaching scaffold:** the hello-world product supports explanation and tracing;
- **assessment evidence:** students' independently expanded lanes demonstrate their own decisions;
- **research evidence:** only separately consented records may be analyzed as research data.

## Front-end scope boundary

Theoretical explanation covers Astro rendering/content, localized routing, islands architecture,
Svelte interaction, React streaming state, browser offline behavior, accessibility, testing, and
performance. Containers and service processes are named only so students can run and trace their
local system. Cloud operations and server administration are not teaching objectives in this plan.
