## 0. What this phase actually is

`services/mcp/server.py` is the **runtime domain MCP** — a FastMCP server, internal port `3001`,
exposing tools that call into `ttod_core` (read-only) to fetch quotes/graph neighborhoods by
tag/section, and to score retrieval confidence for R1's `/api/v1/oracle/stream` endpoint. It is
**distinct from and unrelated to the IDE development MCP** in `.cursor/mcp.json` (an Astro docs
server, for contributors' editors only — it never runs inside the container network and this
runbook never touches it).

**Runtime transport frozen after implementation review (2026-09-05):** serve FastMCP Streamable
HTTP at `/mcp`. R1 receives the service base URL as `MCP_SERVER_URL`, appends `/mcp`, and calls
`semantic_retrieval` through `fastmcp.Client`. The stable result envelope is
`{results, indexDigest, indexedQuotes}`; changing it requires coordinated contract changes and
tests, not an implicit server-only edit.

R2 is one of three instructor-owned lanes (with R1 — FastAPI backend, and R3a — walking-skeleton
scaffold) that must all be green before the cohort-start gate opens. R2 and R1 are logically
independent (both depend only on R0) but functionally coupled: R1's `oracle/stream` calls R2's
tools for retrieved wisdom context and confidence scores. Since the same person owns both, this is
a coordination note, not a gate — but the tool contract (tool names, input/output shape) should be
settled before R1's integration code is written against it, or vice versa; whichever is built
first fixes the shape for the other.

## 2. Non-negotiable boundaries (restated in full)

### 2.1 Inherited from TTOD Phase Q — unconditional, no exceptions

- **`ttod.yml` has exactly one write path** (`ttod_core/repository.py` atomic transactions via
  `cli.py`). `services/mcp` is **strictly read-only** — its tools fetch/embed/score, they never
  write anything, not even a proposal (that is R1's `oracle/propose` job, not R2's).
- **No silent provenance promotion.** Any quote R2 returns as retrieval context still carries its
  real `origin` field unmodified — R2 never re-labels or strips provenance.
- **Rights gate.** R2's embedding index is built only from `status: active` quotes with a
  resolved, public-permitted `rights` block — the same filter R1 applies at the API boundary,
  applied here at the embedding-corpus boundary so a restricted quote can never surface as
  retrieval context in the first place.
- **Local-only AI.** Both the embedding model (`nomic-embed-text`) and any model R2 itself might
  call go through Ollama's own API. No OpenAI/Anthropic/cloud embedding or LLM API call anywhere in
  `services/mcp`.
- **Content stays CC BY-NC-SA 4.0** — irrelevant to R2's own output shape (it returns quote IDs and
  scores, not rendered public pages), but the corpus it indexes is the same governed, licensed
  corpus everywhere else in this platform.
- **Counts are never hardcoded.** The number of quotes R2 embeds is read live from `cli.py stats`
  at index-build time, never a fixed number in code or docs.

### 2.2 Inherited from the stack draft, reconciled with studio infra

- **No heavy external DB / no vector DB.** R2 does **not** stand up a separate vector database
  (no pgvector, no Chroma, no Qdrant). "Embed once, cache keyed on `ttod.yml`'s mtime/digest" is
  the whole storage strategy — the same in-process-cache pattern R1 uses for its graph/wisdom-
  sample projections (§2.2 of the master document). The corpus is small enough today (hundreds of
  records) that a full in-memory embed-and-scan on every cache-miss is trivially cheap; if it ever
  grows into the thousands, that assumption should be revisited explicitly, not silently kept.
- **No heavy native dependencies** — must run on an 8 GB RAM student laptop. `nomic-embed-text` is
  a 274 MB model (confirmed locally, §3.2) — this is intentionally light.
- **No unbound host ports.** `mcp-server`'s internal port is `3001`; it is not exposed to the host
  directly in the base compose file — only `backend` talks to it, over the internal container
  network.
- **Ollama is three-tier, not one switch.** R2 never hardcodes a model tag or placement. This
  applies to the embedding model too, not only the chat model — **judgment call, flagged explicitly
  in `PHASE-R0-REPORT.md`:** the master document names `nomic-embed-text` directly in prose (§3
  item 4) rather than through an env var the way it insists for the chat-tier model (§2.2), which
  reads as slightly inconsistent with its own "no runbook may hardcode a model tag" rule. This
  runbook resolves that inconsistency the same direction as the rest of the document: read the
  embedding-model tag from a new env var, `OLLAMA_EMBED_MODEL`, defaulting to `nomic-embed-text` in
  `.env.example` — never a bare string literal in `server.py`. If the product owner intended
  `nomic-embed-text` to be a truly fixed, non-configurable choice, that is a one-line change to
  `.env.example`'s default, not a design change.

### 2.3 Cross-platform constraints

- Root `.gitattributes`: `* text=auto eol=lf`; root `.env`: `COMPOSE_PROJECT_NAME=ttod_oracle`.
- Podman/Podman Compose is the reference orchestrator; plain Docker Compose must also work
  unmodified.

### 2.4 Environment files and secrets discipline

**This stack needs zero real secrets — R2's own tools have nothing to authenticate against beyond
a local Ollama instance with no auth token.** `.env.example` (committed, placeholder-only) gains
`OLLAMA_EMBED_MODEL=nomic-embed-text` alongside the existing `OLLAMA_MODE`/`OLLAMA_MODEL`/
`OLLAMA_BASE_URL` vars R1 already documents there; `.env` itself stays gitignored (already is,
confirm before adding new vars, don't re-add the rule). Never pass a value that looks like a real
secret as a bare CLI argument or log line. If R2's implementation ever seems to need an API key —
it should not, everything here is local Ollama — stop and ask rather than inventing one.

## 3. Domain contract slice R2 works against

R2 does not own `domain.ts`, but its tools' output feeds directly into R1's `OracleResponseChunk`
(`citedQuoteIds`) and the retrieval-confidence score that decides `mode: 'grounded' | 'creative'`:

```typescript
// R1's response envelope — R2's confidence score is the input to the mode decision R1 makes.
export interface OracleResponseChunk {
	mode: 'grounded' | 'creative';
	citedQuoteIds?: string[]; // present only when mode === 'grounded'; sourced from R2's top-k tool result
	text: string;
}
```

R2's own internal tool-result shape (not part of the frontend contract, but must be stable for R1
to integrate against) should return, per query: the top-k retrieved quotes (at minimum `id`,
`text`, `section`, `tags`) **and their cosine similarity scores, not silently dropped after
ranking** — R1's threshold comparison needs the actual score, not just a pre-filtered "good enough"
list.

## 4. Scope — what R2 builds

`services/mcp/server.py`, FastMCP, internal port `3001`. Tools:

1. **Semantic retrieval tool.** Given a query string (and optionally a `contextTag`/section
   filter), embed the query with `nomic-embed-text` (via `OLLAMA_EMBED_MODEL`), compare against the
   cached corpus embedding index, return top-k quotes **with cosine similarity scores attached** —
   not silently dropped after ranking (§0.1's own explicit instruction, restated).
2. **Graph-neighborhood tool.** Given a quote ID or tag/section, return the local graph
   neighborhood (calls the same `ttod_core`/`Exporter` graph-projection code R1's `/api/v1/graph`
   uses, §4.1 of R1's runbook) — used to seed the oracle's context window, not just flat retrieval.
3. **Embedding index build/refresh.** On startup (and whenever `ttod.yml`'s mtime/digest changes),
   embed every `status: active`, rights-resolved quote with `nomic-embed-text`, cache the vectors
   in-process. No persistence to disk required for R2's scope (the walking-skeleton corpus is small
   enough to re-embed on container start in well under a second per hundred records — verify this
   empirically and note the actual measured time in the report; if it turns out to be slow enough
   to matter, that is worth flagging, not silently working around).

**Retrieval-confidence threshold is R1's decision to apply** (§5.2 of `R1-backend-bridge.md`) — R2
only supplies the score, it does not itself decide grounded vs. creative. Keep that boundary clean:
R2 is a pure retrieval/scoring service, R1 owns the policy that consumes it.

## 5. Mechanical gates R2 must pass (restated — exact rows relevant to this phase)

| Gate | Required proof |
| --- | --- |
| Write isolation | `services/mcp` never writes `ttod.yml` and never calls any `ttod_core` write path — R2 is read-only, full stop, no exception (it does not even stage proposals) |
| Provenance | quotes returned as retrieval context carry their real, unmodified `origin` field |
| Rights filter | the embedding index never includes a quote whose `rights` is unresolved/restricted or `status != active` |
| Local AI | no cloud embedding/LLM API call anywhere under `services/mcp` — `nomic-embed-text` via Ollama only |
| Determinism | re-embedding the same unchanged `ttod.yml` snapshot produces the same top-k ranking for a fixed query (embeddings themselves are deterministic given a fixed model/input) |
| Secrets discipline | `.env.example` gains `OLLAMA_EMBED_MODEL` as a placeholder-safe default; no real secret anywhere in `services/mcp` |
| Port isolation | `mcp-server`'s `3001` is internal-only, not host-bound in the base compose file |

## 6. Rollback and mutation law (restated in full)

- The web layer (including `mcp-server`) is read-only against `ttod.yml` under all circumstances;
  a failing MCP deploy never blocks or risks the CLI/data layer, because it cannot touch it.
- Container/image failures never touch host files outside `services/*/`, `caddy/`, and the compose
  files; nothing in R2 writes to `~/.ollama`, `ttod.yml`, `schema/`, or `exports/` except read
  access to `ttod.yml` (via `ttod_core`) and normal Ollama model inference/embedding calls.

## 7. Touched-path budget

**Allowed:** `services/mcp/**` (app code, `Dockerfile`, its own dependency manifest), an `mcp`
service block contributed to root `docker-compose.yml` (R3a owns final assembly — coordinate),
`.env.example` additions for `OLLAMA_EMBED_MODEL`.

**Forbidden:** `ttod_core/*.py`, `schema/*.json`, `ttod.yml` (read-only import only), any
container/dependency scaffolding beyond `services/mcp`'s own directory, `services/backend/**`
(that is R1's, even though R2's output feeds it — integrate through the tool contract, not by
editing R1's files).
