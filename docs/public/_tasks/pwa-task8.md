# Assignment — Team 4, Task 8: Open one PR into a module you don't own

**Seam:** offline · **Team:** 4 · **Task:** 8 of ~10
**Area(s):** PWA/Offline · **Verb served:** contribute

For Team 4 (PWA & Local Operations), this task requires identifying a genuine improvement or fix within a module owned by another team (such as Content, Graph, Oracle, or Accounts) and submitting a Pull Request that demonstrates a deep understanding of that foreign codebase. This is not a superficial typo fix; it is a substantive contribution that proves you can navigate, read, and modify code you did not write, serving as critical process evidence of your ability to collaborate across module boundaries.

See the shared explanation: docs/public/teaching/tasks.md#the-three-recurring-tasks

> "The module that knows its boundaries serves the whole. The module that knows no boundaries becomes the whole—and collapses under its own weight."
> — TTOD `arch-001`, *architecture*

This task enforces the discipline of respecting module boundaries by requiring you to engage with another team's domain as a contributor, not an owner, ensuring your changes integrate cleanly without assuming ownership of the entire system.
