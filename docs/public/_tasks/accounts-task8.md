# Assignment — Team 5, Task 8: Open one PR into a module you don't own

**Seam:** accounts · **Team:** 5 · **Task:** 8 of ~10
**Area(s):** Accounts · **Verb served:** contribute

For Team 5, this task requires you to identify a genuine improvement or fix within a module outside your primary scope—such as the `wisdom` content pipeline, the `graph` visualization components, or the `oracle` prediction logic. You must read the existing codebase of that module to understand its conventions and constraints, then submit a pull request that integrates cleanly with their architecture. This is not a drive-by typo fix; it is a demonstration that you can navigate and contribute to code you did not author, respecting the boundaries and patterns established by the module's owners.

See the shared explanation: docs/public/teaching/tasks.md#the-three-recurring-tasks

> "The module that knows its boundaries serves the whole. The module that knows no boundaries becomes the whole—and collapses under its own weight."
> — TTOD `arch-001`, *architecture*

This task tests your ability to respect those boundaries: by contributing to a module you do not own, you demonstrate that you can serve the whole system without imposing your own architectural preferences on it.
