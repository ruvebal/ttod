## Diagram brief

**Audience:** UDIT Front-End II students preparing Entrega 1 and the Units 1–7 mid-term.  
**Learning goal:** Name where document rendering, content/i18n, islands, streaming UI state, the browser↔service boundary, offline hello-world, a11y, and test layers live — then defend those seams like the mid-term asks.

**Question to answer:** What does the browser own, what does Astro own, what do islands own, and where does trust cross into HTTP?

**Hard constraints:**
- `diagram_type: architecture`; `meta.quality_profile: showcase`; `meta.locale: en`
- Title: `TTOD ↔ FE II — Front-end Architecture (Units 1–7)`
- 8–11 components only — FE-track vocabulary on every label
- Exactly **one primary path** (`emphasis`): Browser → Astro document (SSR/routes + content collections + `es`/`en`) → page shell → multi-framework island (Svelte Graph **or** React Oracle — one on the main path) → HTTP/SSE → Oracle FastAPI → governed quote snapshot → accessible UI state
- Side branches only from the nearest main-path node:
  - Astro → content collections / i18n contract (Units 2–3)
  - Content collections + page shell → Service worker **Cache-First** (Unit 4 / Entrega 1): built wisdom/docs pages are the offline corpus — not an Oracle-only stub
  - React Oracle → IndexedDB offline queue when API is unreachable (Network-First API); Ollama remains online-path only
  - Honest card: the PWA/`public/sw.js` milestone is student-owned; reference `main` may only expose Caddy `/sw.js` headers + `db.ts` queue until the cohort ships the SW
- Ownership boundaries (student-readable; map to Entrega 1 defence language):
  1. **Document ownership (U2–U3)** — Astro owns HTML, SSR/islands shell, localization, content-oriented routes
  2. **Island ownership (U3)** — Svelte/React own interactive state; they do not own the document
  3. **Service boundary** — browser may call `/api/*`; it never writes `ttod.yml`
- **Cards (no extra edges)** — one card per concern, FE II–synced wording:
  - Entrega 1 expansion areas (content IA, graph exploration, Oracle recovery, offline ops, test strategy)
  - Testing stack: Vitest + RTL + Playwright; layers unit → component → contract → route → a11y (U5)
  - Performance: measure before claiming (U7); containers only run the stack — not the syllabus
  - Assessment sync: Entrega 1 25% + Mid-term U1–7 15%; process + understanding > black-box demo; AI disclosure required
- Exact names: `services/frontend` (Astro), content collections, Svelte Graph island, React Oracle island, Caddy `:8080`, `/api/v1/oracle/stream`, `ttod.yml` snapshot, Ollama `localhost:11434`, Vitest, RTL, Playwright
- Student language: `document`, `island`, `SSE`, `snapshot`, `es`/`en` — avoid studio jargon (`ttod-bridge`, blackbox, C14N, pgvector) unless one card glosses “governed snapshot”
- Guided views (≤3), titled like course seams:
  1. Primary request path (browser → snapshot → UI state)
  2. Document vs island ownership (Entrega 1 architecture defence)
  3. Streaming Oracle + recovery / offline boundary (U3–U4)
- Pin repository evidence from `~/src/ttod` when paths exist; sparse edges; omit `via`/`labelAt` until the validator demands one

**Do not invent:** CDN, cloud auth, multi-tenant SaaS, Kubernetes, MCP as a student deliverable, or a second primary path.  
**Do not draw:** Entrega 2 (R3F / shaders / IoT / Python WebSocket), Entrega 3 / oral defence capstone, CLI quote mutations, or proposal inbox — those are other diagrams or later units.
