Status is an evidence claim

From rich reference to teachable baseline

The roadmap uses state words carefully. “Implemented” means code exists; “locally observed” means a behavior was exercised in one environment; “verified” requires the named evidence and review; “proposed” authorizes no implementation or release by itself.

Now

  • The governed core and schema programme are implemented.
  • The multilingual data model and most bilingual work are implemented; further language work remains proposed.
  • The rich instructor reference contains the major content, graph, and Oracle areas.
  • An end-to-end local run has been observed, with independent verification still open.
  • The application is not a public cloud service.

Next: teaching-baseline work

  1. Freeze contracts: inventory the rich reference and classify each behavior as keep, reduce, assign, or exclude.
  2. Preserve the reference: retain a recoverable instructor artifact outside student reach.
  3. Reduce advanced interfaces: keep one complete content, graph, and streaming interaction in each lane.
  4. Expose unfinished seams: add the smallest observable offline/operations and testing examples.
  5. Assemble a fresh-history baseline: distribute no hidden answer through objects, history, remotes, bundles, or metadata.
  6. Rehearse the theory: teach and test the exact artifact before collaboration opens.
  7. Reconcile research and calendar: keep artifact identity, claims, assessment, and consent aligned.
  8. Synchronize localized course tracks: update English and Spanish FE II materials so Entrega 1 and the Units 1–7 mid-term name the same TTOD baseline, only after the preceding gates pass.

Independent publication lane

This Jekyll site is a documentation-only release. It can publish project and research information while the application remains local. It does not implement the student-owned app deployment, PWA, or CI/CD assignment.

Release gates

  • Zero public-privacy findings in source and rendered output.
  • Valid internal links and a warning-free Jekyll build.
  • No private operational identifiers or local filesystem coordinates.
  • Honest status and research language reviewed for each audience.
  • Continuing disclosure, secret, and reachable-history review for the public repository.
  • Human authorization before student distribution, course synchronization, research collection, or application deployment.
