## 0. What this phase actually is, and the gate you must verify before starting

R3a built the thinnest possible working slice: a hello-world route and one live-fetched quote,
already i18n-routed (`/en/`, `/es/`). R3b is where the **actual documentation site** gets built on
top of that skeleton — MDX content collections presenting the TTOD wisdom corpus as browsable
documentation, with Tailwind design tokens and a real layout, in both required locales.

**Do not start this phase until you have personally confirmed the cohort-start gate is open** —
read `docs/DEV_PLAN/PHASE-R1-REPORT.md`, `PHASE-R2-REPORT.md`, and `PHASE-R3a-REPORT.md` and
confirm each says `DONE` (not `PARTIAL`, not `BLOCKED`). If any of the three is not `DONE`, stop and
flag it rather than building against an unfinished backend — R3a's own runbook is explicit that a
`PARTIAL` R3a does not open the gate. **Also read `PHASE-R3a-REPORT.md`'s own "Lessons for the next
phase" section in full before writing any code** — if R3a's cold review changed anything about the
Caddy setup, the compose wiring, or the `domain.ts` contract, that change applies to you before you
start, not after you discover it the hard way.

**Dependency note (§6 of the master document, restated):** R3b depends on the cohort-start gate
(R1+R2+R3a), **not on R4 or R5**. You do not need to wait for the graph or oracle islands to exist
— your content routes and their layout are independent of those two islands, though R6 (PWA/CI/CD)
later depends on R3b, R4, and R5 all being `DONE` together.

## 2. Non-negotiable boundaries (restated in full)

### 2.1 Inherited from TTOD Phase Q — unconditional, no exceptions

- **`ttod.yml` has exactly one write path.** R3b is a **pure frontend consumer** — it never writes
  anything, not even indirectly; it renders content fetched (at build time or request time,
  whichever R1's endpoints support) from `backend`, which is itself read-only.
- **Rights gate public export.** Every quote R3b renders in a content page must have come from an
  R1 endpoint that already applied the rights filter (`status: active`, resolved rights) — R3b does
  not need to re-filter, but it must never bypass R1's API to read `ttod.yml` directly or via a
  cached export file that skips the filter.
- **Content stays CC BY-NC-SA 4.0.** Every rendered quote/page must attribute per
  `LICENSE-CONTENT` — R3a's single-quote page already established the pattern; R3b's job is to
  apply it consistently across every content route, not invent a new attribution format.
- **Counts are never hardcoded.** Any quote/section/tag count shown anywhere in R3b's UI (a
  section index page listing "N quotes," a tag cloud) is computed from a live `backend` response,
  never baked into MDX frontmatter or a static fixture at build time in a way that goes stale.

### 2.2 Inherited from the stack draft, reconciled with studio infra

- **No heavy external DB / no separate content store beyond Astro's own content collections
  mechanism** — `src/content/docs/` MDX files are the content layer for prose/course material; the
  quote data itself still comes live from `backend`, never duplicated into MDX.
- **No heavy native dependencies** — the site must build and run on an 8 GB RAM student laptop.
- **No unbound host ports** — R3b does not touch compose/port configuration at all; that is R3a's
  (already-frozen) territory.

### 2.3 Cross-platform constraints

- Respect the root `.gitattributes` (`* text=auto eol=lf`) already established by R3a — do not
  introduce a file with inconsistent line endings.
- Build/test locally with whatever orchestrator R3a's onboarding doc specifies (Podman Compose or
  Docker Compose) — both must work unmodified.

### 2.4 Environment files and secrets discipline

**R3b does not introduce any new env var and needs no new secret.** It consumes the `.env`/
`.env.example` R3a already created. If you find yourself needing a new configuration value, add it
to `.env.example` with a placeholder-safe default, following R3a's existing pattern — never a real
secret. This stack needs zero real secrets for local dev; if a content-engine task ever seems to
require something that looks like an API key, stop and ask, that would be off-script for this
project.

## 3. Domain contract slice R3b consumes

```typescript
// The shape R3b renders on every content/docs route that displays a quote.
export interface WisdomEntry {
	id: string;
	section: string;
	subsection?: string;
	level: 'beginner' | 'intermediate' | 'advanced' | 'master';
	text: string;
	teaches: string;
	tags: string[];
	related: string[];
	origin: 'human' | 'studio' | 'blackbox' | 'mixed' | 'legacy-unknown';
	lang: string; // ISO 639-1 — filter content by this to keep an /es/ route from silently showing English quotes
	rights: {
		license: string; // e.g. "CC-BY-NC-SA-4.0" — use this exact value for attribution, not display prose
		holder?: string;
	};
}
```

**Do not hand-edit this file.** It is R1's contract; if R3b needs a shape R1 does not yet expose
(e.g. a section-index aggregation), request it as an R1 addition rather than inventing a parallel
client-side shape that could drift.

## 4. Scope — what R3b builds

1. **`src/content.config.ts`** — Astro 5's typed schema for `src/content/docs/` MDX frontmatter (course
   syllabus pages, TTOD philosophy docs) — Astro parses and type-checks against it.
2. **`src/content/docs/` MDX**, written in **both** `en`/`es`, under the locale-routed structure
   R3a already established (`/[locale]/docs/[...slug]`). **Do not ship an English-only page and
   plan to "add Spanish later"** — the route shape already exists (R3a), every page you write goes
   in both languages from the start.
3. **Zero-JS static docs routes** — `/[locale]/wisdom/[slug]` (individual quote pages, live-fetched
   from `backend`, filtered by the route's own locale using `WisdomEntry.lang`) and
   `/[locale]/docs/[...slug]` (MDX prose) — both statically generated where Astro's SSR/SSG model
   allows, no client-side framework required for these routes (React/Svelte islands are R4/R5's
   territory, not R3b's).
4. **Tailwind design tokens** — `@tailwindcss/typography` for MDX prose, a shared token set (color,
   spacing, type scale) that R4's Svelte island and R5's React island can also draw from later, so
   the platform reads as one visual system rather than three disconnected islands.
5. **Section/tag index pages** — browsable navigation across the corpus (by `section`, by `level`,
   by `tags`), all counts computed live from `backend`, never hardcoded.

## 5. Mechanical gates R3b must pass (restated — exact rows relevant to this phase)

| Gate | Required proof |
| --- | --- |
| Rights filter | every rendered quote came from a rights-filtered `backend` response; no route reads `ttod.yml` directly or via an unfiltered export |
| i18n | every content route resolves under both `/en/` and `/es/`; no route ships English-only |
| Counts never hardcoded | any quote/section/tag count in the UI is computed from a live `backend` response at build/request time |
| License | every rendered quote attributes per `LICENSE-CONTENT` |
| Test shape (R7 will assert this, but design for it now) | content/component tests are integration-style (real content rendering), not isolated unit tests of framework internals |

## 6. Rollback and mutation law (restated in full)

- The web layer is read-only against `ttod.yml` under all circumstances — R3b introduces no write
  path whatsoever, it is pure presentation.
- A build/content bug in R3b never touches `ttod.yml`, `schema/`, `exports/`, or any other service's
  code — its blast radius is `services/frontend/src/content/**` and its own routes.

## 7. Touched-path budget

**Allowed:** `services/frontend/src/content.config.ts`, `services/frontend/src/content/**`, `services/frontend/src/pages/[locale]/docs/**`,
`services/frontend/src/pages/[locale]/wisdom/**`, `services/frontend/tailwind.config.*`, shared
design-token files under `services/frontend/src/styles/**`. Shared manifest/lock and Astro
integration changes are owned centrally by the instructor integration lane; R3b consumes the
installed MDX and Tailwind integrations rather than racing sibling agents on those files.

**Forbidden:** root `docker-compose.yml`, `caddy/**`, `.env*` (beyond adding a placeholder var if
genuinely needed, per §2.4), `services/backend/**`, `services/mcp/**`, `ttod_core/*.py`,
`schema/*.json`, `ttod.yml`, `services/frontend/src/types/domain.ts` (read it, don't edit it —
that's R1's contract), R4's/R5's island directories.

## 8. Post-phase cold review (mandatory — not a formality)

Before this phase's report can say `DONE`, a reviewer with **no memory of writing the

per §6.1 of the master document, this is "a different lane's owner, Rubén for a student lane, or a

it**, using the studio's `/code-review` skill (medium effort is enough for a single-lane diff).
"Looks done" is not "is done."

**Two propagation obligations if the cold review finds something:**
1. If the finding only affects R3b itself, fix it and re-review before filing `DONE`.
2. **If the finding is structural — it reveals the master document itself asserted something
   false, not just that this runbook needs a tweak — that gets escalated to amend
   `PHASE-R-TTOD-ORACLE-PLATFORM-CASCADE-PROMPT.md` itself** (the student flags it; the product
   owner/instructor makes the actual amendment, since the master document is instructor-owned).

Record findings in `PHASE-R3b-REPORT.md` under a `## Lessons for the next phase` heading — R6 reads
this report (along with R4's and R5's) before it can start, since R6 depends on all three being
`DONE`.

## 9. Phase report status enum (restated — use exactly one)

- **DONE** — every gate in §5 passed; cold review (§8) ran and its findings are recorded and
  resolved or explicitly deferred; the report shows real evidence, not "should work."
- **PARTIAL** — some content/routes shipped and are individually gate-clean, others are not; name
  exactly which — **R6 cannot start against a PARTIAL R3b** (it needs R3b, R4, R5 all `DONE`
  together).
- **BLOCKED** — cannot proceed because of an external dependency that isn't R3b's own work to fix
  (most likely: the cohort-start gate was not actually open when this phase started, or R1's API
  shape changed underneath it without notice).
- **IN_PROGRESS** — rare for this phase; would apply only to a genuinely long-running content
  translation/authoring pass still mid-flight when the session ends.
