## Checklist answers

1. **Throttle and bypass.** With Compose, the XFF trust boundary holds: Caddy 2.10 has no `trusted_proxies`, so it overwrites client XFF. Astro forwards Caddy's value, and the frontend and backend publish no ports. Every attempt counts, and the guard runs before bcrypt. The 429 text is the same for known and unknown accounts, so there is no enumeration. Password change is constant-time (a dummy hash when the user is missing) and returns the same 401 text as login. It rotates the caller's sid, revokes the others plus all PATs by default, and maps `LookupError` to 401. Legacy PATs are refused. Deny TTL = full PAT TTL, a safe superset of D7's "remaining life". The index is pruned on read. Signed fallback is off in code (`"0"`), in the dataclass, and in Compose. Gaps: F1, F2, F4, F5.
2. **Oracle.** Stream and propose are both gated (tests, plus my live 401/401). Propose goes through the app's store, and it is throttled per user before the Ollama call. No other unauthenticated write path is left: favorites and proposals need a session, and logout is POST with an origin check. The terminal keeps 401/429 out of the queue for new queries (F10 covers replay).
3. **Cookie and Host.** Sound for classroom HTTP: Secure is never set on HTTP, and a spoofed XFP cannot flip it. Behind an external TLS proxy it is not sound (F3). `TTOD_ALLOWED_HOSTS` is validated (`^[a-z0-9.-]+$`, so IPv4 works; say so in `.env.example`) and is really build-time (Dockerfile `ARG`/`ENV` before `npm run build`, Compose `build.args`). The gate's 303 is real evidence. Matching ignores the port (probe: `Host aa2-rev.lan:28280` → 200).
4. **Defaults.** 100 logins / 5 min / IP, 40 registrations / h / IP and 10 / 5 min / account are a reasonable classroom judgement, and they are documented. A cohort larger than 40 on one NAT hits 429 at sign-up. The message ("too many attempts in a row") then blames the student, so add one sentence for the instructor. Compose passes empty strings through, and they fall back to the defaults (verified live).
5. **Changes to existing tests.** These are adaptations, not weakening. `support.py` and the helpers now issue real store rows instead of the signed blobs that F4 refuses, and the oracle tests sign in first. `exclude_none` only affects `display_name`; `AuthLoginResponse` and `TokenResponse` have no other optional fields.
6. **Gate amendments.** (1) The spoof-proof cookie check is fair. It is stronger than the original, which encoded a wrong topology, but no positive Secure check is left (F6). (2) The explicit register budget is fair but does not prove pass-through (F6). I verified pass-through live. (3) The isolated data dirs are fair and strengthen isolation. AA5's own gate still predates the helper (F3).
7. **Legibility.** The `.env.example` block reads well. Report §4 step 3 contradicts itself (F2). §4 says nothing about the external-TLS limitation or the lockout trade-off (F3, F5).
